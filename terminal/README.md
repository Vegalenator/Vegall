# Терминал ИИ-цикла

Рабочий инструмент для отслеживания инвестиционного и финансового цикла ИИ по всем
слоям: кремний, память, литография, сети, серверы, ЦОД, энергетика, облако, модели,
корпоративный софт, конечные применения, капитал и внедрение.

Основание — исследование «ИИ как инвестиционный и финансовый цикл» (срез 6 сентября
2026 года). Ни одной цифры, не прослеживаемой до первичного источника.

Без сборщика и зависимостей: `terminal/index.html` открывается двойным кликом.

## Главная идея конструкции

Терминал измеряет не «сколько потратили», а **разрыв между обязательством и
загрузкой**: какая доля вложенного капитала уже обслуживается внешним денежным
потоком. Поэтому:

- у каждой цифры есть **статус** — факт, оценка, прогноз, заявление руководства,
  экспертная шкала, расчёт терминала или несверенная внешняя проверка;
- серый статус `nodata` означает не ноль, а отсутствие публичного ряда. Пять из
  двадцати восьми показателей панели — именно такие, и среди них фактическая
  загрузка GPU и мегаватт, то есть ключ к окупаемости;
- в графе связей стрелка показывает **направление денег**, а слои разложены по
  течению. Стрелка, идущая вверх, — это деньги, вернувшиеся к тому, кто их дал.

## Как обновлять данные

Все данные лежат в `terminal/data/*.js` обычными объектами. Разметка и логика их
не знают — меняется файл данных, пересобираются все экраны.

| Файл | Что внутри |
|------|-----------|
| `meta.js` | Дата среза, типы утверждений, реестр источников S1-S30 |
| `layers.js` | 13 звеньев цепочки создания стоимости |
| `companies.js` | Финансовые раскрытия и тест пяти условий |
| `network.js` | Узлы и связи графа |
| `indicators.js` | Панель 28 показателей и лестница доказательств |
| `scenarios.js` | Сценарии, ранние индикаторы, группы уязвимости |
| `russia.js` | Россия, география цикла, энергетика |
| `citations.js` | Реестр сверок с первоисточниками: статус, место в документе, цитата |
| `feeds.js` | Состояние подключений. **Руками не правится** — создаётся скриптом |
| `editorial.js` | Редакционный пакет: подводки, тезисы, формулировки, 65 вопросов |
| `history.js` | Снимки состояния. **Руками не правится** — создаётся скриптом |

**Текущий режим — ручное обновление.** Автоматических подключений к источникам в
этой сборке нет, истории значений тоже нет: терминал отвечает на вопрос «как
сейчас», но ещё не на вопрос «что изменилось с прошлого раза».

Планируемые слои обновления:

- **Слой A** — котировки, капитализация, кредитные спрэды. Планируется обновление
  по расписанию.
- **Слой B** — капвложения, потоки, выручка сегментов. Планируется импорт из
  машиночитаемых раскрытий.
- **Слой C** — IEA, BIS, Census, Банк России, iKS, связи графа. Останется ручным:
  эти организации не отдают данные машиночитаемо.

Добавляя связь в `network.js`, укажите `inReport`: `yes` — связь описана в
исследовании, `mechanism` — механизм описан, компании не названы, `no` —
общеизвестное раскрытие вне исследования. Терминал показывает это различие в
таблице связей и позволяет оставить только проверенные связи.

## Четыре вопроса на главном экране

Главный экран собран не по темам, а по порядку работы перед эфиром:

1. **Что изменилось** — движение индекса к прошлой сборке, список изменений по
   существу, столбики индекса по снимкам.
2. **Чем подтверждено** — сработавшие стресс-сигналы с источниками, перечень
   пробелов, субиндексы с достаточностью данных, три опорные цифры.
3. **Какой вывод допустим** — ступени лестницы доказательств, разнесённые на
   «что можно утверждать» и «чего утверждать нельзя», плюс формулировки.
4. **Какой вопрос задать эксперту** — вопросы из исследования, чья тема совпадает
   с тем, что сейчас сдвинулось, подаёт стресс-сигнал или не обеспечено данными.
   Рядом с каждым вопросом написано, почему он выбран именно сейчас.

Подбор вопросов объясним: тема вопроса определяется ключевыми словами (поле
`tags` в `editorial.js`), «горячие» группы — изменениями с прошлого снимка,
стресс-сигналами и нехваткой данных. Никакой скрытой логики.

## Круговые контуры

Переключатель «Круговые контуры» на экране графа гасит всё, что не входит в
замкнутые круги, обводит каждый круг красным и пускает по его связям бегущий
пунктир в направлении денег. Наведение на круг открывает карточку: как идут
деньги, что видно в отчётности, чем опасно, какой сигнал тревоги называет
исследование и что проверять. Щелчок закрепляет карточку, Escape снимает.

Контуры ищутся автоматически. Разбор рисков лежит в `VG_LOOP_RISKS` в
`network.js`, ключ — участники через « + » в алфавитном порядке. Контур,
найденный без разбора, получает общий текст из исследования (тезис 8).
Нумерация идёт по силе доказательств: сначала контуры, где все связи описаны в
исследовании, затем подтверждённые отчётностью, затем остальные.

Контуров восемь (на 07.11.2026). Что подкреплено отчётностью и первоисточниками:

- **Alphabet ↔ Anthropic** — Alphabet во II квартале 2026 года отразил $98,0 млрд
  прочего дохода, в основном от нереализованной переоценки долей, при
  операционной прибыли $40,8 млрд: ровно тот сигнал, который исследование
  называет тревожным. В III квартале он стал убытком (−$8,2 млрд). Доля Alphabet в
  Anthropic и её размер ни в одном прочитанном документе не названы — эта связь
  держится на раскрытии вне исследования.
- **Amazon ↔ Anthropic** — Amazon назвал источником внеоперационного дохода
  во II квартале ($53,4 млрд) «investments in Anthropic».
- **Microsoft ↔ Anthropic** и **Microsoft ↔ OpenAI** — Microsoft называет вложение
  в Anthropic в отчётности, а условия договоров с Anthropic ($30 млрд Azure,
  вложение до $5 млрд) и с OpenAI (≈27%, +$250 млрд Azure) подтверждены
  объявлениями сторон.
- **Nvidia → Anthropic → Microsoft → Nvidia** — вложение Nvidia до $10 млрд,
  закупка Azure на $30 млрд, закупка ускорителей Microsoft у Nvidia.
- **Nvidia ↔ CoreWeave** — форма 10-Q CoreWeave: пакет Nvidia куплен по $87,20.

Контуры с пометкой `weak: true` (Nvidia → Anthropic → Amazon/Alphabet → Nvidia)
найдены автоматически, но возврат денег к Nvidia по этим веткам косвенный:
Anthropic покупает у Amazon и Google в основном их собственные чипы (Trainium,
TPU). Они всегда стоят в конце нумерации и подписаны как неподтверждённые.

**Правила для новых связей и контуров.**
1. Связь вне исследования (`inReport: 'no'`) обязана иметь `src` и `cite` на
   первоисточник: отчёт эмитента или объявление самой стороны сделки. Связь без
   первоисточника остаётся в графе только с явной пометкой в `basis`
   (сейчас так — `Alphabet → Anthropic`, доля).
2. Каждая новая связь автоматически может породить новые контуры (одно
   вложение Nvidia создало сразу три). Для каждого нового контура пишется разбор
   в `VG_LOOP_RISKS`; если возврат денег по цепочке не подтверждён — `weak: true`.
3. Суммы «до» — обязательства, а не платежи; так и писать.
4. Контур — взаимная зависимость, а не доказанный возврат тех же денег.

**Рынок в карточке контура.** Блок «Рынок с 6 сент.» собирается при показе из
`data/market.js`, а не пишется в разбор, поэтому не устаревает. Для непубличных
участников (Anthropic, OpenAI) пишется «не торгуется»: их цену задаст размещение.
Поле `stake: { sym, price, usd }` в разборе включает расчёт биржевой стоимости
пакета (сейчас — пакет Nvidia в CoreWeave). Это биржевая цена, а не
бухгалтерская переоценка.

**Открытые пробелы.** Проспект Anthropic (S-1 от 26.10.2026, S-1/A от 02.11.2026) не
прочитан: размер архива sec.gov и требование к заголовку запроса. До цены
размещения доли Amazon, Alphabet и Microsoft переоцениваются по последнему
раунду (Series H, $965 млрд); цена размещения станет следующей точкой. В граф не
внесены Micron, Samsung и SK hynix (вошли в раунд H как стратегические партнёры,
суммы не раскрыты) и соглашение со SpaceX на GPU-мощности.

## Котировки

`python3 build/connect.py --market` собирает дневные закрытия за год (API Nasdaq — акции США, ADR и фонды; ISS Мосбиржи — Яндекс и Сбер) и пишет `data/market.js`. Страница в сеть не ходит: это снимок на момент сборки, экран так и подписан.

Котировки **не входят** в индекс напряжения. Индекс считается по 28 показателям исследования — отчётность, мощности, энергия, — и меняется, только когда показатель пересекает порог. Рынок реагирует раньше: падение бумаг — ранний сигнал негативного канала (стр. 13 исследования), а не его наблюдение. Поэтому на главном экране они стоят рядом в блоке «Рынок против панели», а не смешаны в одну цифру. Решение добавить рыночную группу в индекс — методическое, требует новой версии методики (`VGM.METHOD`) и пересчёта истории.

Цвета дивергентной шкалы — синий (рост) и красный (падение) с серым у нуля: различимы при дальтонизме и не спорят со статусными цветами панели. Знак процента подписан всегда.

## Сверка с первоисточниками

Ссылка на источник — ещё не проверяемость. Поэтому у утверждений есть не только
код источника, но и запись сверки в `citations.js`: где именно в документе
утверждение и что там написано дословно.

| Статус | Что означает |
|--------|--------------|
| `verified` | Первоисточник открыт, формулировка найдена дословно |
| `partial` | Подтверждено частично: другая формулировка или значение из графика |
| `mismatch` | По указанной ссылке утверждения нет |
| `unreachable` | Источник не открывается из среды сборки (обычно 403) |
| `pending` | Сверка не проводилась |

Чип рядом с цифрой показывает статус, наведение открывает цитату, нажатие ведёт
в реестр на экране «Источники». Там же видна очередь сверки — расхождения,
недоступные источники и непроверенное.

Состояние на 20 сентября 2026: сверено дословно 26 из 46, частично 5,
расхождение 1, источник недоступен у 10, не сверялось 4. Доля сверенного
записывается в снимок истории, поэтому прогресс проверяемости виден в журнале
обновлений наравне с движением индекса.

Найденное расхождение стоит того, чтобы его назвать: сумма €200 млрд инициативы
InvestAI по указанной в исследовании ссылке не подтверждается — на странице
Еврокомиссии речь о конкурсе гигафабрик ИИ и более чем €30 млрд инвестиций.

## Подключения к первоисточникам

```bash
python3 build/connect.py --list        что подключено и в каком состоянии
python3 build/connect.py --run-all     забрать документы и сверить величины
python3 build/connect.py --apply nvda  перенести расхождение в данные
python3 build/connect.py --selftest    проверить, что отказы срабатывают
```

**Подключение никогда не пишет в данные само.** Оно забирает документ, разбирает
величину вместе с дословной цитатой, проверяет определения — единицу, период,
диапазон и то, что документ вообще является нужным релизом, — и кладёт
предложение в `build/proposals/`. Перенос величины остаётся решением человека.

Почему так строго. Страница несуществующего квартального релиза Nvidia отвечает
кодом 200 и молча уводит в архив новостей. Подключение, доверяющее коду ответа,
записало бы в терминал пустоту. Поэтому источник считается подтверждённым только
при совпадении содержимого, а каркас проверяется самотестом на четырёх случаях:
страница несуществующего релиза, документ другого эмитента, выручка сегмента
больше общей, величина вне физически осмысленного диапазона.

Успешный запуск обновляет дату и цитату в реестре сверок: подключение и есть
механизм сверки.

Подключено: Nvidia и ASML, квартальные пресс-релизы. Определения каждой величины
записаны в `build/connectors/*.py` и показываются в терминале рядом с числом.

Не подключено и почему: IEA, SEC, Amazon, Broadcom, Oracle, TSMC и Meta отвечают
отказом на запрос из среды сборки. Рыночный слой (котировки и кредитные спрэды)
остаётся неподключённым: FRED не отвечает, Stooq отдаёт JS-заглушку, Yahoo
возвращает 429, AlphaVantage требует ключ.

Новое подключение — это модуль в `build/connectors/` с полями `SPEC`, функциями
`parse` и `check`. Определение каждой величины обязательно: без него
автоматическое обновление однажды подменит одно понятие другим.

## История значений

Каждое обновление данных фиксируется снимком:

```bash
python3 build/snapshot.py "обновили отчётность Nvidia за III квартал"
python3 build/snapshot.py --list                  # что уже записано
python3 build/snapshot.py --rev <коммит> "метка"  # снимок состояния из истории репозитория
```

Снимок считается модулем `assets/metrics.js` — тем же кодом, который выводит
числа на экран. Поэтому история и интерфейс не могут разойтись, а экран «Что
изменилось» показывает ровно то, что произошло с данными.

Три правила, на которых это держится:

1. **Снимки пересчитываются действующей методикой.** В снимке хранится состояние
   данных, а не картинка экрана. При изменении шкалы или весов поднимается
   `METHOD` в `metrics.js`, и вся история пересчитывается заново — иначе смена
   методики выглядела бы как движение рынка.
2. **Показатели сравниваются по `id`, а не по названию.** Название можно
   переписать, не потеряв ряд. Для ранних сборок, где идентификаторов ещё не было,
   работает сопоставление по названию.
3. **Если данные изменили без снимка**, экран «Что изменилось» выводит
   предупреждение с числом расхождений: сравнение показывает прошлое, пока снимок
   не зафиксирован.

Давность проверки живёт в самих показателях: `checked` — дата сверки наблюдения с
источником, `cadence` — ожидаемая периодичность обновления в днях. По истечении
периодичности показатель помечается как требующий проверки, а в шапке терминала
видно общее число таких показателей.

## Методические ограничения, которые нельзя терять при доработке

- **Индекс напряжения — среднее авторских оценок, а не измеренная степень
  перегрева.** Норма 0, наблюдение 50, стресс 100; веса групп выбраны экспертно и
  не проверены на исторических данных. Показатели без публичного ряда в расчёт не
  входят, поэтому рядом с каждой группой выводится достаточность данных, а группа
  с покрытием ниже 60% помечается как необеспеченная.
- **Столбики сравнимы только внутри одной длины периода.** Квартал, полугодие и год
  разнесены по блокам; компания, у которой раскрыт прирост, а не уровень
  капвложений, из сравнения исключается (сейчас это Amazon).
- **Отношение капвложений к операционному потоку** измеряет способность компании
  финансировать стройку собственными силами, а не окупаемость вложений именно в ИИ:
  операционный поток создаётся всем бизнесом компании.
- **Замкнутый контур в графе** означает взаимную зависимость сторон, а не
  доказанный возврат одних и тех же денег: доля в капитале, облачный кредит,
  подписанный договор и совершённый платёж — разные экономические события.
- **Тест пяти условий** выносит отрицательный вывод только по нарушенным условиям.
  «Публично не наблюдаемо» считается отдельно и нарушением не является.
