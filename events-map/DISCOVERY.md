Ты пополняешь «Карту событий» — редакционный календарь для ведущего вечернего шоу на деловом радио. Страница: https://claude.ai/artifact/QzU5btiQM5G2J1CVWQjacW. Данные лежат в базе артефакта; страницу не перепубликуй, работай только с базой через ArtifactData (загрузи через ToolSearch: "select:ArtifactData,WebSearch,WebFetch"). В git ничего не коммить. Итоги, заявления и сверку дат делает другой прогон — ты только ищешь и добавляешь НОВЫЕ события.

Главное правило: статус даты — обещание ведущему, который произнесёт дату в эфире. confirmed — только при официальном анонсе организатора (сайт мероприятия, пресс-релиз, указ, решение избиркома). Даты из агрегаторов и календарей мероприятий без подтверждения организатора — preliminary. Известно только окно («осенью», «в декабре») — expected.

## Схема документа `events/<id>`
- title, kind (Заседание / Выборы / Форум / Саммит / Публикация данных / Отчётность / Срок / Пресс-конференция / Конференция / Выставка), cats — массив из: russia, intl, elections, cb, business, stats, tech
- type — тип события (задаёт цвет на странице), ровно одно из: monetary (решения ЦБ, ФРС, ЕЦБ, выступления их глав), elections (выборы и референдумы), summits (саммиты, встречи министров, международные форумы), state (парламенты, правительства, бюджетные сроки, пресс-конференции глав государств), data (публикации статистики), energy (ОПЕК+, энергетические форумы), corp (корпоративная отчётность), tech (технологические и отраслевые форумы, конференции, выставки)
- geo {lat, lon, place} — точка на карте в карточке: координаты города проведения (для выборов — столицы страны), place — подпись «Город, Страна» или просто страна; для онлайн-событий geo = null
- where; start / end — ISO-время с поясом +03:00 (Москва); allDay — true, если время не известно
- dateStatus: confirmed | preliminary | expected | cancelled
- для expected и cancelled: start = null, window = "YYYY-MM-DD" (крайняя дата окна), dateWording — фраза для эфира («в октябре, дата не назначена»)
- timeNote, dateNote, risk (коротко, например «Высокий риск переноса»), dateSource {name,url}, checkedAt "YYYY-MM-DD"
- ideaWording (дословная формулировка International IDEA), ideaCheck (что показала сверка) — только для выборов, где IDEA расходится с фактом
- participants; agenda [{text, basis:"agenda"}] — только то, что подтверждено повесткой/документом
- scenarios [{text, basis:"agenda"|"analysis"}] — возможные решения; analysis = предположение редакции
- impact {russia, business, markets}; checkpoint {what, when, date}
- sources [{name,url}]; phase: upcoming | closed; updatedAt
- outcome {expected, decided, open:[...], sources:[{name,url}], filledAt ISO, filledBy:"claude", backfilled:false}
- statements [{date "YYYY-MM-DD", who, role, kind: "quote"|"paraphrase", text, source {name,url}}] — заявления по итогам дня события; quote — только дословная цитата из стенограммы или прямой речи в источнике (без кавычек внутри text), иначе paraphrase
- airBrief — справка «Для эфира»: 3–5 коротких фраз радийным языком, как ведущий дал бы справку в эфире. Суть события, когда и где, чего ждать или чем закончилось. Без скобок, аббревиатур без расшифровки и канцелярита; числа — так, как их произносят. Дата — строго по статусу: confirmed называй прямо, preliminary — «ориентировочно» и с оговоркой, expected — только окно и «дата пока не назначена», cancelled — «не состоится».
- changes [{at ISO +03:00, kind, from, to, note, source {name,url}}] — журнал изменений карточки, по нему страница строит «Ленту изменений» и метки «изменено» / «новое». Только дописывай в конец, старые записи не трогай. kind: new, date (перенос даты или окна), time, status (сменился dateStatus), cancel, agenda, outcome, other. from / to — коротко, как произнёс бы ведущий: «октябрь, без даты» → «22 октября»; note — одна фраза, почему; source — основание.
Все тексты — на русском, коротко, в тоне редакционной карточки.

Не добавляй общие слова и неоднозначные сокращения. Запись — update с if_version.

## Порядок прогона
1. Прочитай всю коллекцию `events` (action list, query.limit 1000), чтобы не создавать дубликаты (сверяй по названию, датам и месту).
2. Найди новые события на горизонт трёх месяцев от текущей даты. Цель — 10–15 новых карточек за прогон, только действительно значимые. Два направления:
   **А. Макро и политика.** Анонсы Правительства России (government.ru), Кремля, Госдумы; календарь Росконгресса; календари ООН и Совета ЕС (consilium.europa.eu, раздел forward look); перечень выборов International IDEA (idea.int/democracytracker/elections-list, сверяй с избиркомами); расписания Банка России, ФРС, ЕЦБ и других крупных ЦБ; графики Росстата и BLS; ОПЕК, МВФ, G20, БРИКС, ШОС, ЕАЭС.
   **Б. Отраслевые и технологические события (type "tech", в cats обязательно "tech").** Форумы, конференции и выставки, где выступают первые лица крупных компаний, министры, регуляторы или где объявляют сделки и продукты: ИИ, ИТ, финтех, телеком, кибербезопасность, венчур и стартапы, промышленность и робототехника, энергетика и новые материалы, биотех и медицина, космос, транспорт, ритейл и e-com. Источники: сайты организаторов (Сбер, Яндекс, ВТБ, Т-Банк, Ростех, Росатом, «Сколково», Агентство инноваций Москвы, Минцифры, Минпромторг, Банк России — Финополис), ict2go.ru, all-events.ru, totalexpo.ru, TAdviser, CNews, ComNews, отраслевые СМИ; зарубежные — Web Summit, GITEX, Slush, CES, MWC и подобные. Приоритет: чем выше уровень спикеров и чем важнее для бизнеса и рынков — тем важнее. Узкие профессиональные митапы не бери.
3. Для каждого нового события заполни карточку целиком по схеме выше: type, cats, geo, start/end или window, dateStatus с dateSource, participants, agenda, scenarios, impact, checkpoint, sources, airBrief. Не выдумывай участников и повестку — пиши только то, что есть в анонсе; ожидания помечай basis "analysis".
3а. Каждой новой карточке сразу пиши changes: [{at: текущее время, kind: "new", note: "Добавлено ежедневным поиском событий", source: {name, url} — анонс, по которому добавлено}].
4. Если у существующего события нашёлся официальный анонс, которого раньше не было (дата, время, программа, спикеры), обнови его карточку с if_version и перепиши airBrief. Если при этом изменились дата, время, статус или повестка — допиши в changes запись с kind date / time / status / agenda, from → to и источником (передай массив целиком с новой записью).
5. Записывай батчами (action batch, до 50 записей), новые документы — op "set" без if_version.
6. В конце обнови `meta/status` (с if_version): в начало log добавь запись {at:"ДД.ММ ЧЧ:ММ", text:"поиск: новых N (макро N, отраслевых N — перечисли коротко), обновлено N, проблемы: …"}; lastRunAt не трогай; храни не больше 20 записей.
7. Не выдумывай. Если дата не подтверждена — так и отметь статусом.
